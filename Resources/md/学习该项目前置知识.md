## 一、启动项目（最低要求）

| 知识领域 | 具体内容 | 掌握程度 |

| **Maven** | `mvn clean package`、`mvn install`、依赖管理 | 能编译项目即可 |
| **MySQL** | 安装、建库、用户密码配置 | 能执行 SQL 即可 |

### 1.2 启动流程核心概念

```
基础设施启动 → Nacos配置发布 → MySQL建库 → 按顺序启动微服务 → 网关最后启动
```

只需理解：
- 服务启动后会自动注册到 Nacos
- 网关是所有请求的统一入口
- 配置从 Nacos 动态拉取，不在代码中硬编码

### 3.2 修改一个微服务的典型流程

以"给课程服务添加一个新接口"为例：

```
1. 在 tj-api 模块定义 DTO
   tj-api/src/main/java/.../CourseDTO.java

2. 在 course-service 的 Controller 添加接口
   @RestController
   @RequestMapping("/course")
   public class CourseController {
       @GetMapping("/newEndpoint")
       public List<CourseDTO> newMethod() { ... }
   }

3. 在 Service 层实现业务逻辑
   @Service
   public class CourseServiceImpl implements CourseService { ... }

4. 在 Mapper 层实现数据访问
   public interface CourseMapper extends BaseMapper<Course> { ... }

5. 如需被其他服务调用，在 tj-api 中定义 Feign 接口
   @FeignClient("course-service")
   public interface CourseClient { ... }

6. 重新编译并启动
   mvn clean package -pl tj-course -am -DskipTests
   java -jar target/tj-course.jar --spring.profiles.active=local

7. 通过网关访问
   GET http://127.0.0.1:10010/cs/course/newEndpoint
```

### 3.3 配置修改速查表

| 需求 | 修改位置 |
|------|---------|
| 改数据库连接 | Nacos 对应服务的 `xxx-service.yaml` |
| 改 Redis 连接 | Nacos `shared-redis.yaml` |
| 改日志级别 | Nacos `shared-logs.yaml` |
| 改网关路由规则 | `tj-gateway/src/main/resources/application-local.yml` |
| 改 JWT 密钥 | `tj-auth-service/src/main/resources/tjxt.jks` |
| 改服务端口 | 对应服务 `application.yml` 中 `server.port` |
| 禁用/启用 Seata | Nacos 各服务配置中 `seata.enabled` |
| 改 AI 模型配置 | Nacos `aigc-service.yaml` 或 `application-local.yml` |

#### RAG（检索增强生成）

| 知识点 | 说明 | 项目中的应用 |
|--------|------|------------|
| 文档分块（Chunking） | 将长文档切分为小块进行向量化 | 课程信息分块存储 |
| 向量嵌入（Embedding） | 将文本转为向量表示 | Redis Vector Store |
| 相似度检索 | 根据向量距离找到最相关的文档块 | 检索课程知识 |
| 上下文注入 | 将检索到的文档块注入到 Prompt 中 | Advisor 自动完成 |
| 重排序（Reranking） | 对检索结果重新排序提高准确性 | 可选优化 |

**RAG 工作流程：**
```
用户提问 "Java 课程有哪些？"
    ↓
1. 将问题向量化（Embedding）
    ↓
2. 在 Redis Vector Store 中检索相似文档
    ↓
3. 将检索到的课程信息注入到 Prompt
    ↓
4. LLM 基于注入的上下文生成回答
    ↓
5. 返回 "我们推荐以下 Java 课程：..."
```

### 4.3 多智能体架构

#### 智能体核心概念

| 概念 | 说明 |
|------|------|
| Agent（智能体） | 能感知环境、做出决策、调用工具的 AI 实体 |
| 路由智能体 | 分析用户意图，决定交给哪个子智能体处理 |
| 工具调用 | 智能体通过 Function Calling 调用外部 API |
| 记忆机制 | 短期记忆（对话上下文）+ 长期记忆（MongoDB） |

#### 项目中的智能体设计

```
Agent（智能体接口）
  ├── RouteAgent（路由智能体）
  │     → 分析用户意图（推荐课程？购买咨询？普通聊天？）
  │     → 路由到对应子智能体
  │
  ├── RecommendAgent（推荐智能体）
  │     → 调用 CourseTools 查询课程
  │     → 基于 RAG 检索课程知识
  │     → 生成推荐结果
  │
  └── BuyAgent（购买决策智能体）
        → 调用 CourseTools 获取课程详情
        → 调用 OrderTools 查询订单状态
        → 提供购买建议
```

#### Function Calling 工作原理

```

         ↓
1. LLM 分析意图，决定调用 OrderTools.queryOrder()
         ↓
2. Spring AI 框架自动调用 Java 方法
   OrderTools.queryOrder(userId, courseName)
         ↓
3. Java 方法查询 MySQL 返回订单数据
         ↓
4. 框架将结果返回给 LLM
         ↓
5. LLM 基于结果生成自然语言回答
   "您的 Java 课程订单已支付，可以开始学习了"
```
